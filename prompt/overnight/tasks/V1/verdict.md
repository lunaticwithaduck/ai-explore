## Findings (non-blocking follow-ups)
1. **`reviewAuthor` clips the name by code points, but the rules and `reviewSchema` count UTF-16 units.** At `utils/reviewAuthor.ts:20`, `[...value].slice(0, 60)` can return up to 120 units when the name holds astral characters such as emoji. The create batch is then denied with a translated `permission-denied`. This happens only on the fallback path (auth `displayName`), when the profile name is missing or still loading. The profile name is used first, and it is already ≤ 60 units through the rules and A1's `profileSeed.ts:7`, which clips with `.slice`. Nothing desyncs, but such a user cannot post until the profile loads. Fix: clip to 60 UTF-16 units (`value.slice(0, 60)`, then drop a trailing lone surrogate).
2. `ReviewsSection.test.tsx` has 203 lines. The 200-line rule in CLAUDE.md is enforced by `lint-conventions` only for non-test files (`scripts/lint-conventions.cjs:55-61`), so it passes the gate.
3. `reviewsSectionStyles.separator` is unused (`ReviewsSection.styles.ts`).
4. If the reviews query fails, `ReviewComposer` keeps its skeleton (`own` stays `undefined`) under the translated error. `RatingSummary` renders nothing on error. This is cosmetic.
5. In the hand-back's ToolHeader note, the header data refreshes on reload or navigation (`force-dynamic`), not on "revalidation".
6. `toolReviews` reads the whole subcollection without a limit, and the worker already flagged this. It is fine at seed sizes.
